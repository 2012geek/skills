# GitCode PR Review Comment Repair

Automatically repair GitCode PR review comments using LLM-generated fixes.

## When to Use

Use this skill when:
- User provides a GitCode PR link with unresolved review comments
- User wants to automatically fix code review feedback
- User mentions "修复检视意见" (repair review comments) or similar
- User needs to respond to multiple review comments systematically
- User wants to automate the fix-reply-commit workflow

## Workflow

The repair process follows these steps:

1. **Parse PR Link** - Extract owner, repo, PR number from URL
2. **Get Review Status** - Fetch resolved/total comment count (hybrid: API + web scraping)
3. **Calculate Unresolved** - `unresolved = total - resolved`
4. **Check Completion** - If all resolved, exit with success message
5. **Fetch Unresolved Comments** - Get each review comment with file, line, and content
6. **Generate Fixes** (for each comment):
   - Use Anthropic Claude to analyze code and review comment
   - Generate fix OR detect flawed review logic
   - Prepare structured reply with fix details
7. **Reply to Comments** - Post replies to each review comment via GitCode API
8. **Apply Code Fixes** - Edit files based on fix suggestions
9. **Commit** - Use `git commit --amend` to update the commit
10. **Output Summary** - Display table with all fixes and review comment links

## LLM Integration

The skill uses Anthropic Claude (claude-3-5-sonnet) to:

1. **Analyze** the review comment and surrounding code context
2. **Determine** if the review is valid or if the logic is flawed
3. **Generate** precise code fixes with before/after comparison
4. **Explain** the reasoning for fixes or disputes

### LLM Prompt Structure

The prompt sent to Claude includes:
- File path and line number
- Full review comment text
- Relevant file content (20 lines of context)
- Clear instructions for output format

### Response Parsing

The LLM response is parsed into structured fields:
- `HAS_FIX`: Whether code modification is needed
- `NEEDS_REPLY_ONLY`: Whether only a clarification reply is needed
- `FIX_DESCRIPTION`: Brief explanation of the fix
- `ORIGINAL_CODE`: Exact code to be replaced
- `FIXED_CODE`: The corrected code
- `REASON`: Explanation for disputed review comments

## API Integration

### GitCode API Methods

- `getPRComments(prNumber)` - Fetch all PR comments
- `getReviewStatus(prNumber)` - Get resolved/total counts
- `replyToComment(prNumber, commentId, body)` - Post reply
- `getFileContent(path, ref)` - Get file content
- `calculatePosition(patch, line, isNewFile)` - Calculate diff position

### Hybrid Status Detection

The skill uses a hybrid approach for getting review status:

1. **Try API first** - Use GitCode API to get comment counts
2. **Fall back to scraping** - Use Puppeteer to scrape "评审意见已解决X/Y" text
3. **Parse and calculate** - Extract resolved/total numbers and compute unresolved

## Troubleshooting

### API Authentication Error

```
Error: GitCode token not configured or invalid
```

**Solution**: Add `gitcode.token` to config.json with a valid personal access token with `repo` and `pull_request` scopes.

### LLM API Error

```
Error: Anthropic API key not configured
```

**Solution**: Add `anthropic.apiKey` to config.json:
```json
{
  "anthropic": {
    "apiKey": "sk-ant-..."
  }
}
```

### Git Amend Error

```
Error: Git operation failed
```

**Solution**: Ensure:
- You're in a git repository
- You have uncommitted changes to amend
- You're on the correct branch
- Git is properly configured

### Web Scraping Fails

```
Error: Could not find review status div on page
```

**Solution**: The PR page HTML structure may have changed. The skill will fall back to API-only mode if available.
