## 📚 理论基础（快速版）

### Claude Code 是什么？

**Claude Code** = 代理式 AI 编程工具，不仅仅是代码助手，而是能够：
- 📝 直接编辑文件（不是建议代码）
- 🧠 理解整个代码库
- ⚡ 执行命令（测试、构建、Git 操作）
- 🎯 自主规划（Plan Mode）

### 两种形态对比

| 特性 | CLI 版本 | VSCode 扩展 |
|------|----------|-------------|
| **更新速度** | 🚀 最快 | ⏱️ 稍慢 |
| **功能完整性** | ✅ 100% | ✅ 95% |
| **图片输入** | ❌ 不支持 | ✅ 支持 |
| **适用人群** | 熟练开发者 | 新手/可视化偏好 |

### Skills 系统核心

```
Skills = 可复用的能力模块

├── Commands（斜杠命令）→ /commit, /review-pr
├── Agents（子代理）→ code-reviewer, pptx-generator
├── Hooks（事件钩子）→ PreToolUse, SessionStart
└── Scripts（执行脚本）→ build.js, test.py
```

**核心价值**：模块化 + 可复用 + 可组合 + 可扩展

### 案例1：代码检视 Skill

**📦 对应 Skill**：[gitcode-code-review](https://github.com/2012geek/mylerobot-doc/tree/main/skills/gitcode-code-review)

#### 🎯 问题背景
- **业务场景**：开发团队需要人工审查每个 PR，耗时耗力
- **痛点**：
  - 人工审查容易遗漏细节
  - 审查标准不一致
  - 重复性工作多

#### 💡 解决方案
集成官方 code-review agent，实现自动代码检视

**技术架构**：
```
用户提交 PR
    ↓
触发 code-review agent
    ↓
分析代码变更
    ↓
生成审查意见
    ↓
自动评论到 PR
```

```python

```


#### ✅ 最佳实践

> 💡 **核心建议**
> - 使用 **LLM 语义分析**，避免规格性描述（如"函数不超过50行"）

#### ⚠️ 调试过程中的坑

**坑1：样例当成答案**

调试测试用例时，没有明确告诉 Claude 不要调整 PR 描述，结果把 PR 描述改坏了

```markdown
❌ 错误指令：
"参考以下样例生成测试用例：[样例内容]"

✅ 正确指令：
"参考以下样例生成测试用例模板（不要修改PR描述）：[样例内容]"
```
---

#### ✅ 最佳实践

> 💡 **核心建议**
> - 模板要足够详细，否则每次生成结果不一致
> - 明确标注样例，避免被当成答案

> ⚠️ **常见误区**
> - 给样例时必须明确"这是样例，参考格式"
> - 调试一部分时，要锁定其他部分

## 🎯 快速开始

### 选择合适的版本

```bash
# 新手或偏好可视化
→ 使用 VSCode 扩展

# 熟练开发者或需要完整功能
→ 使用 CLI 版本

# 需要图片输入
→ 必须使用 VSCode 扩展

# 自动化脚本
→ 使用 CLI 版本
```

### Skills 开发建议

1. **从小处着手**：先实现简单功能
2. **充分测试**：在不同场景验证
3. **明确边界**：清晰定义职责范围
4. **复用优先**：查看官方仓库避免重复
5. **渐进式开发**：使用 Plan Mode 探索代码库
